# 2. 后续开发总原则

继续沿用课程设计尺度：

> **以当前真实代码为基础，只做高收益、可完整闭环的改动，不机械复刻全部历史 Gate 设计。**

Gate 1～4 后续继续用于：

```text
需求 / 架构方向
+
边界与禁止项
+
冲突裁决
```

而不是企业级施工清单。

已经冻结的问题只允许因以下原因 reopen：

- 真实 Bug；
- 回归；
- 新权威冲突；
- Cloud 实施暴露的真实阻塞；
- 明确人工授权。

## 2.1 课程设计型朴实码风

v1.7 建立的长期规则继续有效：

> **代码首先要让本人、老师和后续维护者容易读懂、容易解释、容易调试；不以“看起来高级”作为质量标准。**

统一要求：

- 代码简洁、直接、可读；
- 文件、函数和逻辑分块清晰；
- 命名表达真实业务含义；
- 优先普通循环、条件、STL 容器和清楚的函数调用；
- 不为了“工程化”增加空壳层、单次 wrapper 或无收益泛型化；
- 不为了“朴实”机械删除有真实用途的现代 C++。

以下能力可以继续正常使用：

- `std::vector`；
- `std::optional`；
- `std::unordered_set`；
- `std::filesystem`；
- `enum class`；
- `std::sort`；
- RAII；
- 正常 Qt signals / slots / lambda / Model-View。

判断标准：

```text
必要
+
清楚
+
可解释
+
收益大于复杂度
```

## 2.2 注释与文件结构

注释用于解释：

- 业务规则；
- 非显然约束；
- 持久化 / 状态机 / stable-ID 事实；
- 必要兼容背景。

不保留无代码语义价值的实现过程备注、AI 工具过程备注或逐行翻译代码的注释。

文件结构继续追求：

```text
职责明确
+
一眼能看出模块
+
不过度拆分
+
不过度堆叠
```

文件长度本身不是拆文件理由。

## 10.5 可复现 Release 工作流

正式 tracked 入口：

```text
scripts/build_release.ps1
```

开发 / clone 后工作流：

```text
git clone
↓
一次性配置 Qt 6 Widgets + matching MinGW + CMake + Ninja
↓
.\scripts\build_release.ps1
↓
release/校园雷锋日记.exe
↓
双击运行
```

构建要求与运行要求严格区分。

### Build machine

需要：

- PowerShell；
- CMake；
- Ninja；
- Qt 6 Widgets；
- matching MinGW g++；
- `windeployqt`。

### Deployed runtime

不需要：

- Qt 安装；
- MinGW 安装；
- CMake；
- Ninja；
- 手动 `set PATH`；
- CMD / PowerShell 启动程序。

脚本不硬编码本机：

```text
E:\Qt
C:\Users\admin
LEIFEN~2
```

而是：

- 从 PATH 发现工具；
- 从 `windeployqt` 推导 Qt prefix；
- 从脚本位置推导项目根目录；
- 非 ASCII 项目路径动态尝试 Windows 8.3 路径；
- 无可用 ASCII-safe 路径时明确停止。

执行顺序：

```text
fresh configure
↓
build
↓
CTest
↓
staging deployment
↓
runtime/data verification
↓
source-data safety check
↓
replace release/
```

只有 staging 验证通过后才替换正式 `release/`。
