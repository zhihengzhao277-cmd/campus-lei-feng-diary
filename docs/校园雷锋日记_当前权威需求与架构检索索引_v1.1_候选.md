## 权威性顺序

发生表述冲突时，按以下顺序裁决；排在后面的文件只可补充细节，不能推翻前面的当前结论。

1. 本索引中的“当前项目状态”和“硬性覆盖规则”。
2. Gate1 v1.5、Gate2 v1.3 中与“学生申请下架日记”有关的明确撤销表述。
3. Gate3.1～3.7 对应章节顶部的当前状态，以及其中的冻结决定、设计理由、文本架构图、流程图和实现备注：它们定义最终业务架构。
4. Gate3.9 D259～D276：它是**当前唯一的程序版本路线、实现顺序、版本验证门槛与最终交付映射依据**；不得用它重写 Gate3.1～3.7 的最终架构。
5. Gate3.8 当前状态与图示问题登记；原图仅可作问题定位，不能推翻文字冻结架构。
6. `Gate3_90_跨Gate治理与追溯档案.md`：用于跨 Gate 覆盖、无编号规则、迁移追溯与历史裁决的定位；历史内容不得单独作为当前规则来源。
7. Gate1 v1.4、Gate2 v1.2、Gate3 v2.4 原文件、`Gate3_90` 内的历史部分，以及《版本迭代规则与 Gate 3 架构原则 v1.1》被覆盖的版本路线：仅作历史追溯。
